# ركلة | RAKLA — The Shop

A bilingual Kuwaiti football equipment storefront built as the school project "The Shop".

## Run & Operate

- `pnpm --filter @workspace/rakla run dev` — storefront, using its managed workflow
- `pnpm run typecheck` — full workspace typecheck, including storefront and API routes
- `pnpm --filter @workspace/rakla run build` — production Next.js build
- `pnpm --filter @workspace/api-spec run codegen` — regenerate API hooks and Zod schemas from the OpenAPI spec
- Required Replit Secrets: `MONGODB_URI` (MongoDB Atlas URI), `JWT_SECRET` (JWT signing secret)

## Stack

- Next.js App Router, React, TypeScript and Tailwind CSS
- MongoDB Atlas with Mongoose; one cached connection helper in `artifacts/rakla/lib/db.ts`
- Passwords: bcryptjs; never store or return plain-text passwords or password hashes
- Sessions: 7-day JWT in the `rakla_session` httpOnly cookie; never localStorage or Authorization headers
- Validation: Zod; API hooks and schemas generated by Orval

## Where things live

- Pages and server API routes: `artifacts/rakla/app/`
- Mongo models, Atlas connection and session helpers: `artifacts/rakla/models/` and `artifacts/rakla/lib/`
- API source of truth: `lib/api-spec/openapi.yaml`; regenerate hooks with the codegen command above.
- Storefront and language/theme: `artifacts/rakla/src/`

## Architecture decisions

- All backend behavior runs in Next.js API routes; there is no separate Express API service.
- The browser calls the same-origin API. MongoDB is accessed only by server code.
- Products are read from MongoDB and the current catalogue is seeded only when the products collection is empty.
- Existing records are retained; first connection maps legacy `displayName` to `name`, `userId` to `user`, and order status `processing` to `pending`.
- Orders are returned only to their owner. A single-order request returns 401 without a valid session and 403 if another user owns it.
- If a required secret is missing, server routes return a clear configuration error; products do not fall back to the bundled catalogue.

## Product

Arabic is the default (RTL), with a complete English (LTR) toggle. The catalogue, accounts and orders use MongoDB through the API. Cart and favorites remain browser-only. Checkout is a school-project order record only; no real payment is collected. The teacher's brand board is at `/brand`.

## User preferences

- Keep `MONGODB_URI` and `JWT_SECRET` in Replit Secrets; never expose them to frontend code.
- Hash passwords with bcryptjs; never store or return plain-text passwords or password hashes.
- Keep every screen bilingual with Arabic/RTL as the default, and use client-side navigation/state without full page reloads.
- Keep order ownership checks on every order endpoint.

## Gotchas

- Next.js requests and sessions use the same-origin `rakla_session` cookie; do not restore Bearer/localStorage authentication.
- Day 5 Stripe and Vercel work is intentionally out of scope.
